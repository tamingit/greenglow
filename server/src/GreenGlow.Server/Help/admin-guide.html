GreenGlow Connect administrator guide

Administrators decide who may connect to which IBM i system, set the session limits, and read the connection log. Everything here is on the Administration page: choose it in the terminal's menu (only administrators see it). Changes take effect at once, for everyone.

Connections

A connection is one IBM i system people can open sessions on. The Connections tab lists them as cards, with a card at the end to add one.

Field What it is
Name An internal name in lowercase letters, digits and dashes, such as prod. It can't change later: sessions and the log refer to it. To rename, add a new connection.
Label What users see on tiles and tabs, up to 40 characters.
Address tls://host:992 for Telnet over TLS, or tcp://host:23 for plain Telnet. Production is always tls://. Plain Telnet sends sign-on passwords unencrypted, so use it only for a test system that offers no TLS; the server warns about it when it starts.
Sessions per user How many sessions one person may have open on it at once (1 to 9, default 3). The IBM i allows three per user (QLMTDEVSSN), ACS included, so more rarely helps.
Enabled A disabled connection is hidden from everyone, administrators included.
Test system Automated sign-on tests may run on it. Never tick it for production.
Colour Shown on the system's tiles and tabs, to tell systems apart. Users may choose their own colour, which wins for them.

Save keeps changes to a card. Delete removes the connection: sessions already open on it carry on, and no new ones can start.

Each card is tagged with what to look out for:

  • not encrypted: a tcp:// address.
  • certificate not verified: TLS, but no CA is trusted for it (see below).
  • test system, disabled, and how many sessions are open now.

Who may use it

Under Who may use it, add Entra ID groups (Add a group) or people (Add a person). Anyone in one of the groups, or named, sees the system and may open sessions on it. × takes access away.

A connection nobody has access to is for administrators only. Add a new system, try it yourself, then give it to a group. Group membership is read from Entra ID and kept for five minutes, so someone just added to a group may wait that long. If Entra ID can't be reached, people who rely on a group are refused until it can.

Certificates

For a tls:// connection GreenGlow checks the IBM i's certificate against the CA the server was given (Relay__CaPem), and against a CA you trust for that connection on its card. With neither, the connection is still encrypted but the IBM i isn't verified: users see a yellow lock and the card says certificate not verified.

  1. On the connection's card press Check certificate. GreenGlow connects and shows the certificates the IBM i sent: who each is for, who issued it, when it expires and its SHA-256 fingerprint. Compare the fingerprint with the one your IBM i administrator gives you.
  2. Press Trust for its CA. If the IBM i doesn't send its root CA, paste the root's PEM (from the Windows certificate store or your IBM i administrator) and press Trust this CA.
  3. If the certificate is for another name than the address, GreenGlow asks before accepting that name. Connections then require exactly that name.

Stop trusting removes it. Trusting and removing a CA are written to the connection log.

Connection log

The Connection log tab records who connected, from which address, to which system, and when. It holds metadata only: never what was on a screen or typed.

  • Each host session is a row (Host session), and so is each browser that showed it (Browser, with the person's role: owner, view-only or full access). Trusting or removing a certificate is a row too.
  • Each printer output sign-on (Printer output) is a row with the IBM i user and how many spooled files were opened, never which. A refused printer sign-on is a row that ends at once and says why, such as sign-on failed: wrong password.
  • Draining, resuming or resyncing a node (Server node) is a row with who asked.
  • Rows still open are current: they show current, and a current host session shows its IBM i user and screen title.
  • With more than one GreenGlow server, Node says which one wrote each row. Rows from the other servers arrive within a minute, and their current sessions show without an IBM i user or screen title.
  • Why it ended says how a session closed: signed off, lost, ended by its user, and so on.

Search finds a user, IP address, device or IBM i user. Show picks the kind of row, From and To a period, and Current only what is open now. The log shows 100 rows at a time: Show older loads more. Download CSV saves the rows loaded so far, so load what you need first.

Nodes

The Nodes tab lists each GreenGlow server (node) with its state, version and open sessions: who, on which system, the device, the IBM i user, the screen, when it was opened, how many browsers show it and since when it has had none. Servers share their connections, users, shares, macros and settings, so a change made on one reaches the others within a second or two. Refresh reads them again.

  • Drain before restarting a server: it opens no new sessions (users opening one are told to open it again, to use another server), and the sessions it has carry on until they end. When they have, restart it. Resume undoes a drain; a restarted server is always active again.
  • A session can't move to another server. A server that stops with sessions open ends them; the IBM i keeps a signed-on user's job for 5 minutes, but the program they were in usually ends.
  • Resync from scratch replaces a server's connections, users, shares, macros and settings with the other servers' copies, if it has gone wrong. Changes it made that no other server has yet are lost. It is refused when no other server answers.
  • A server that can't be reached shows unreachable and why; one whose syncing fails shows the last error.

Administrators

Find someone under Add an administrator to make them one; they don't need to have signed in yet. Remove takes it away, and Remove me your own. The last administrator can't be removed. The initial administrator is set in the server's configuration (Entra__InitialAdminUpn) and becomes one again whenever they sign in.

Settings

The session limits. Each starts at the server's configured default; a value saved here wins, and Use the default goes back.

Setting What it does Default
Browsers per session How many of its owner's own browsers may show one session at once. People it is shared with don't count. 2
Minutes kept with no browser How long a session stays open after its last browser leaves, so its user can come back to it after a reload or a lost network. 0 ends it at once. 5
Sessions on the server The most sessions open at once on each server, across everyone. A new session over it is refused. 50

Good to know

  • Every session runs on the GreenGlow server, so the IBM i sees the server's address, not the user's PC. The connection log has each user's own address.
  • Device names are GG, the server's number and a session number, such as GG1002, reused as sessions end, so GreenGlow adds few device descriptions on the IBM i. A user whose session ended while signed on gets the same name back for 5 minutes, so the IBM i can offer to recover their job.
  • Passwords typed on the sign-on screen pass through the server inside the session, and are blanked before any screen leaves it: no browser, log or shared viewer ever gets one.
  • A user who can't see a system needs a grant on its card (or to be in a group that has one), and the connection must be enabled.
